# V1 技术评估与结论（2026-10-16）

## 实验可复现性

GitHub Actions 成功通过 5 项本地测试和 SMAP P-1 全流程运行，输出 `metrics.json`、`heldout_predictions.csv`、`simulated_feedback.jsonl`。随机种子和时间窗口划分写在 `scripts/run_v1.py`，本分析基于首轮远程真实运行。

## 数据条件

- 数据：SMAP 卫星 P-1 目标遥测值（单通道）；原始正常训练序列 2,872 点，带真实异常区间标签的测试序列 8,505 点。
- 时间切分：测试序列前 2,600 点为监督训练段，中间 1,400 点为验证段，最后 4,505 点为保留测试段。
- 保留测试段真实异常比例为 309/4,505 = **6.86%**。原始异常标签只有二分类，并无物理故障或健康度真值。
- 数据转换版本缺少 Telemanom 的命令/工况上下文；P-1 原异常序列以 *contextual anomalies* 为主，不可将其等同于确认故障。

## 1. 真实异常标签上的检验

| 指标 | 测试值 | 解读 |
|---|---:|---|
| Average Precision / PR-AUC | 0.0568 | **低于**以测试异常发生率估计的随机排序 AP 基准 0.0686 |
| ROC-AUC | 0.3668 | 低于随机排序的 0.5 |
| 精确率 | 0.0664 | 警报中只有约 6.64% 命中真实标注异常 |
| 召回率 | 0.9450 | 极高召回以近乎全面预警为代价 |
| F1 | 0.1241 | 不能满足实用的报警要求 |
| 验证集决策阈值 | 0.0069 | 极低，说明预测置信分数难以区分目标事件 |

**结论**：这套单通道、单事件训练的监督 RF 异常检测器在保留事件上的泛化失败，不能以此充当可靠在线异常预警器。需要更多训练故障事件与命令/运行上下文；不能宣称已区分正常工况漂移和真实故障。

## 2. 三状态代理分类的消融实验

注意：本节的 `degraded_proxy` 和 `fault_proxy` 人工由异常区间**前 20%/后 80%** 划分，绝非真实卫星退化/故障。

| 模型 | 代理状态 macro-F1 | 代理状态多类 Brier（越低越好） |
|---|---:|---:|
| 两级逻辑回归 | 0.3253 | 0.32329 |
| 两级逻辑回归 + HMM 近似滤波 | 0.2527 | 1.02350 |
| HMM 概率 + 异常证据融合 | 0.3115 | 0.57061 |

- 加入 HMM 时序先验后，结果明显**变差**，说明所估计的转移模型与代理标签/判别式观测概率适配不佳。
- 进一步加入异常检测证据后，相比 HMM 有改进，但与最简单的两级逻辑回归相比，依然没有可靠提升。
- 这里仅验证框架计算通路通畅，**不支持**“融合优于单模型”的技术结论。
- 本 V1 采用判别式 HMM 近似（分类概率除以训练先验），而非完整标定的生成式 HMM。

## 3. MSF-MOFS 子集

工程特征 **25 → 2** 维；仅 50 次不同子集包装器评估。选择阶段训练折 G-mean=0.90421，**不能**推断时间保留测试集同样好。

原论文面向 100–22,283 维等高维任务；本次仅 25 维，三种引导初始化大小变为 1/2/5。这不是原论文的完整高维基准复现。应增加“全部 25 特征”对照和更高维的时序/跨通道特征，以避免过分稀疏导致泛化下降。

## 4. 模拟用户评分映射

- 默认权重：100 / 60 / 0。
- 合成用户目标权重：96 / 74 / 12，另加随机噪声；用户输入仅模拟真实运行窗口的专家打分。
- 从验证区间选取 168 条模拟评分，拟合有序约束权重 92.024 / 75.084 / 7.660。
- 保留测试段上，相对**合成分数** MAE：22.874 → **21.830**，略有下降但仍较大，主要受状态概率误差影响。
- 这不是专家评分准确性评估；未收集任何实际维修或人工打分真值。

## 5. V1 验收与未解决问题

**完成**：真实遥测与标注入库，MSF-MOFS、基础三状态概率/HMM、原始时序监督异常模型、验证集拟合的融合模型、用户评分映射、模拟维修反馈、单位测试与可复现 CI。

**尚未实现/没有证据**：真实三级故障识别、真实专家打分、命令/工况漂移识别、自动增量模型更新、在线更新防退化污染、跨设备/跨通道泛化、维修诊断建议正确性或效率提升。

## 6. 后续实验优先级

1. 恢复原始 25 维 SMAP P-1（包括命令输入），并加入 P-4/G-7 等多通道、完整对照；保留严格测试区间，测试整体 AP 而非 point-adjusted F1。
2. 增加真实异常检测基准（Telemanom / 经典无监督正常基线）及监督模型多种窗口/特征消融。
3. 在验证集上选择是否启用 HMM/融合，若仍不优于基础分类器，应提供可解释的安全回退。
4. 获取真实工况、维修和健康度真值后，才评估“健康/退化/故障”和自适应更新许可；必要时设计可控故障注入数据集。
5. 实现由人工确认触发的受控离线更新，再研究自动化更新门控。
