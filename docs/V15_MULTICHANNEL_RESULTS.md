## 1. 数据及方法

目标为 \`channel_29\`，额外输入 \`channel_30\`、\`channel_31\`，三者在官方 \`channels.csv\` 中属于同一子系统、同一物理单元。采用预冻结的 10 分钟历史观测重采样、64 小时窗口（16 点、窗口终点间隔 4 个网格点）。其中 \`channel_30\` 与目标同在官方 group 4，\`channel_31\` 在 group 7。通道选择先于本次模型评价。

**评价任务仅检测目标通道官方 Anomaly：**
- 0 = 目标和上下文均为通常正常；
- 1 = 目标官方 Anomaly，即便其他上下文也异常；
- 2 = 任一输入通道的官方 Rare Event；在本实验里仍算正常负类，但单独审计；
- 3 = 缺口/无效，或只有上下文通道异常（目标未标异常）的时刻。任何窗口跨越 code 3 都不参与评价；此口径保证单通道与多通道比较使用同一目标标签。
- 没有把官方异常转换成物理设备故障。

网格交集共 736,415 点。派生标签数量为：普通正常 679,826、目标异常 10,929、rare 40,841、不可评价 4,819。

以**三个通道中出现的全部官方事件 ID 的时间范围**确定共同 train/validation/test 切点；不允许任何选定通道的官方事件 ID 穿越切点。目标 \`channel_29\` 中可评价的异常 ID 数量：训练 29 / 验证 9 / 测试 10。训练、验证、测试窗口：106,642 / 40,412 / 35,779，训练正常参考抽样 20,000 窗口。所有因果窗口严格限制于各自分区内部。

注意：事件 ID 时间隔离只是去掉跨分区的同一个 ID，并不能证明不同 ID 是独立物理故障。

## 2. 模型选择与测试对照

只在验证集 AP 最大化时选模型，所有 6 个候选由 3 个固定模型 × 单通道/三通道构成。各自阈值为**验证正常窗口的 99.8% 分位数**，连续 3 个评价窗口超过阈值才发告警，缺口重置。测试仅做事后评估，不依据测试选新模型。

| 方法 | 验证 AP | 测试 AP | 测试 AUROC | 测试官方 ID 告警覆盖召回 | 测试官方 ID 新告警触发召回 |
|---|---:|---:|---:|---:|---:|
| Robust level / 单通道 | 0.130929 | 0.017769 | 0.486331 | 4/10 | **0/10** |
| iForest / 单通道 | 0.114700 | 0.014318 | 0.519667 | 0/10 | 0/10 |
| Ridge forecast / 单通道 | 0.052193 | 0.011523 | 0.527202 | 0/10 | 0/10 |
| **Robust level / 三通道（验证选中）** | **0.151483** | **0.018680** | 0.572917 | 4/10 | **0/10** |
| iForest / 三通道 | 0.108053 | 0.010324 | 0.488246 | 1/10 | 1/10 |
| Ridge forecast / 三通道 | 0.056729 | 0.011323 | 0.537279 | 0/10 | 0/10 |

测试异常窗口 354 / 35,779，基准发生率 0.009894。所选方法测试 AP 0.018680，在数值上高于发生率基准，但不足以满足运维性能要求。

**最重要的结果：** V1.4 事件召回指标检查的是“异常时间区间是否被告警覆盖”，但已有告警可以在异常发生前开始。本版将“首次告警触发事件”定义为严格的告警 False→True 边沿必须发生在官方目标异常的评估区间内。选中模型虽然覆盖四个 ID，但 **0 个官方 ID 真正触发了新告警**。覆盖型事件召回不应被描述成发现新异常的能力。

选中模型的其他测试指标：正常告警窗口 6,374 / 32,172（19.81%）；rare nominal 告警窗口 1,550 / 3,253（47.65%）。false alarm *onsets* 为 6 次，按整段约 994 天折算 0.181 次/30 天。但一个告警可持续很长时间，所以“误报事件很少”掩盖了**过高的报警时间占比**。两类指标应同时给出。历史 \`false_alarm_episodes=10\` 为按标签切分后计算的误报区间数，不能和原始告警状态 False→True 触发次数混淆。

## 3. 重要独立性审计：测试事件跨版本重复

当前 V1.5 测试的 10 个 ID：

\`id_156, id_161, id_162, id_171, id_46, id_178, id_179, id_181, id_188, id_189\`

与 **V1.4 channel_21 测试集 ID 完全重合（10/10）**。

因此，V1.5 对每个新模型的训练/验证/测试**内部**采用全局 ID 隔离，但从整个项目已观察过的异常事件角度来看，V1.5 绝不是一个真正未见的事件集。以前的其他通道实验已经曝光同一批 ESA 事件，故本次只能视为**有预冻结配置的探索性跨通道复测**，不能升级为独立确认性证据。

用于论文最终效果验证应选尚未曝光的不同 mission、官方 event class 或外部卫星数据（例如独立的 OPS-SAT-AD），明确审计事件实体重合、工况阶段及跨通道重叠后再冻结最后测试集。

## 4. 技术结论

1. 简单加入两个同子系统传感器，对验证 AP 的提升未能转化成有用的实际告警触发能力；iForest 与 Ridge 在三通道下的 AP 反而下降。
2. 同源异常/rare nominal 的排序区分仍不稳健；误报持续时间高于业务可能接受的范围。
3. 严格的事件报警**新起点**指标比“事件被已存在报警覆盖”更能反映新异常发现能力；建议后续同时报告并以严格指标为主。
4. 下一阶段主线应包括官方高时间分辨率、事件类别分层、可证明有工况关联的遥控指令、残差/模式条件化正常参考，而不是继续调此已曝光测试集的阈值。
5. Telemanom-ESA 官方 LSTM/Dynamic-Threshold 实现尚未复现，不能把 Ridge 预测模型称作 Telemanom。
6. 动态贝叶斯健康状态分支仍不具备真实物理三级健康标签；**不进行异常融合、不宣称真实故障诊断准确率**。

本版 GitHub Actions 历史运行中的前两次失败仅因 Pandas 混合时间字符串解析，已在修复代码后通过 SHA-256 校验的同一份数据重跑；没有因为任何测试成绩修改已冻结实验参数。
